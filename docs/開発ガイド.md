## 全体の仕組み

```
App.tsx
 └─ AuthProvider            … ログイン中のアカウントを全体に配る（企画書 §10）
     └─ 未ログインなら LoginForm、ログイン済みなら↓
     └─ ViewerProvider      … AuthContext の currentUser をそのまま viewer にする
         ├─ ProfileEditor       … プロフィール編集（開いているときだけ表示）
         ├─ PostManager         … 自分の投稿の編集/削除（開いているときだけ表示）
         ├─ AnnouncementBanner  … お知らせ。ラベルを一切見ない（企画書 §6）
         ├─ PostForm            … 投稿フォーム（企画書 §3、6マス）
         └─ Timeline
             … 「提供します」「求めています」「🔍 ラベルを探す」の3タブ（企画書 §5）
             ├─ タブ=検索のとき: LabelSearch
             │     └─ CourseFinder（履修科目専用。学部/学年で絞り込み→ⓘでCourseInfoCardと関連投稿を1枚表示）
             └─ タブ=提供します/求めていますのとき:
                   LabelFilterBar（履修中の講義／所属サークルはまとめボタン）
                   + タブ=求めていますのときだけ CourseRequestFilter
                   + 絞り込んだ投稿一覧
                     └─ ReplyThread … 返信の表示・投稿（企画書 §7）
```

投稿フォーム・投稿編集の履修科目タグも、検索タブと同じ絞り込み（`lib/useCourseDrilldown.ts`）を`CourseTagPicker`経由で使う。ⓘボタンや共有パネルは持たず、タグの選択だけができる。

データの流れ：

1. `src/data/*.ts` に最初のサンプルデータがある
2. 初回だけ `localStorage` に書き込まれ、以降はそこから読む（`src/lib/storage.ts`）
3. 投稿・返信の追加や状態変更は `usePosts` / `useReplies`（`src/hooks/`）を通す
4. 表示直前に `timelineFilter.ts`（ラベル絞り込み）→ `timelineMix.ts`（範囲外を混ぜる）の順で並び替える

## 型とサンプルデータ

`src/types.ts` が企画書 付録B の ER 図をそのまま型にしたもの。テーブルを増やす／列を増やすときは、まず付録Bの図を直してからここを直す。

`USER_LABEL` と `POST_TAG` は独立した配列ではなく `User.labelIds` / `Post.tagLabelIds` に畳んである。中間テーブルの行そのものが必要になったら、そのとき型を戻す。

`sampleCourseInfos`（`src/data/courseInfos.ts`）は `sampleAnnouncements` と同じ固定サンプルで、`storage.ts` を通らない。担当教員名は必ず架空にし、連絡先（メール・電話・部屋番号）は型にも書かない。学部・学年は自由記述にせず、必ず既存のLABELのid（`facultyId`/`gradeId`）で持たせる（CourseFinderのプルダウン絞り込みがこれを前提にしている）。

`labels.ts`の履修科目のうち100件（`l-course-*`）と、`courseInfos.ts`の対応する100件は、群馬大学の公開シラバス検索（ログイン不要、学部横断）から科目名・科目番号・開講期・対象学年だけを取得し、それ以外（教員名・試験配点・授業計画など）はこちらで作った架空の内容を組み合わせたもの。実際のシラバス本文は使っていない。手動でシラバスの内容そのものを追加したいときは、既存の3件（`ci1`〜`ci3`、`l-sub-toukei`など）と同じ形式に合わせる。

## 動作確認のコツ

- 起動すると最初はログイン画面。ログイン画面の下にある「デモ用アカウント」から名前を押すと、共通パスワード `demo1234` でそのままログインできる
- 別のデモアカウントでログインし直す（ログアウト→別の名前でログイン）と、非公開の返信の見え方が変わる（`p1` の教科書に非公開の返信を2件、サンプルとして入れてある。佐藤あかり／渡辺葵でログインすると見え方の違いが分かる）
- 「サンプルデータに戻す」ボタンで、書いた投稿・返信を消して最初の状態に戻せる。**登録したアカウントやログイン状態は戻らない**（別のlocalStorageキーのため）。アカウントごと最初の状態に戻したいときはブラウザの開発者ツールで `localStorage.clear()` を実行する
- ラベルを1つも選んでいない状態は「すべて表示」（企画書 §5）。ラベルを選ぶと絞り込まれ、選んだ数が1つ以上のときだけ「範囲外の投稿を混ぜる」のチェックボックスが出る
- 「🔍 ラベルを探す」タブ内の履修科目は、学部・学年のプルダウンで先に絞り込んでから科目のⓘを押すとシラバスが見える。チップ（フィルタ用）とⓘ（詳細表示用）は別ボタンなので、押し間違えても選択条件は変わらない。統計学のⓘを押すと、統計学タグの「提供します」投稿（`p18`）が下に出る
- 投稿フォーム・投稿編集・プロフィール編集のどの画面でも、履修科目タグは学部・学年のプルダウンで絞り込んでから選ぶ形になっている（`lib/useCourseDrilldown.ts`を共有）。全件フラット表示に戻っていないか確認するときはここを見る
- 投稿の種類（PostKind）は「モノ・手伝い・情報」の3つ（企画書 §3）。「情報」は一度削って戻した経緯がある（README §3参照）ので、`PostForm`・`PostEditForm`の`KINDS`配列が3つとも揃っているか、型変更時は特に確認する
- 「受け渡し・やり取りの場所」は`kind === "情報"`のときだけ任意（`PostForm`/`PostEditForm`の`placeRequired`）。物理的な受け渡しがないオンライン中心のやり取りに、場所の入力を強制しないため。新しくkindごとの分岐を増やすときは、この`placeRequired`のような「モノ・手伝いだけ必須」というパターンをまず疑う
- プロフィール編集で履修科目を「履修中」にすると、Timelineの「表示中のラベル」欄に「履修中の講義」というまとめボタンが出る。「求めています」タブでは、その下に`CourseRequestFilter`（履修中/履修済みの講義だけ・すべて・非表示）も出る
